Table Pro Max 0.3.0 lets you change values directly in a query's results, like you can in an opened table.

If you have 0.1.1 or 0.2.0, the app offers this update itself: a banner appears under the title bar, or go to **Settings › Updates › Check now**. From 0.1.0, install it by hand once; later versions then arrive in the app.

## What's new
- **Edit query results.**
  - Double-click a cell in a query's result grid, or edit it in the row inspector, to change its value or set it to NULL.
  - Edits stay amber until you **Review and commit**. The review shows every UPDATE, and they run in one transaction, even when a join touches several tables.
- **The app only lets you edit a cell it can trace to exactly one row.** The database itself reports which table and column each result column comes from. A table is editable when its whole primary key is in the result.
- **Everything else stays read-only and says why**, in a hint above the grid and when you hover a cell:
  - computed columns (`COUNT(*)`, `price * 2`, functions);
  - a missing key: "Add id to the SELECT to edit users";
  - views;
  - a table that appears more than once, as in a self-join;
  - `UNION`, `INTERSECT` and `EXCEPT`;
  - read-only connections;
  - DuckDB.
- **Safe by construction:**
  - every UPDATE is keyed by the primary key and checks the value you saw. If someone changed the row meanwhile, nothing is written and your edits stay pending;
  - committing refuses to run while the tab has a transaction you opened (`BEGIN`), so it can never commit or roll back your own work.
- **After a commit**, the grid keeps your new values and offers **Run again** to refresh. Running again, or closing the tab, asks first while edits are pending.

## Please read before installing
- **On PostgreSQL**, each SELECT on a writable connection now makes one extra round trip, to learn where the columns come from. It describes the statement and never runs it twice. Read-only connections skip it.
- **On MySQL**, the app can't ask the server whether a transaction is open. It tracks `BEGIN`/`START TRANSACTION`/`COMMIT`/`ROLLBACK` that you run in the tab, and checks `autocommit`. A transaction opened another way, inside a stored procedure for example, is not detected.
- **Query results are read-only on DuckDB.** Editing an opened DuckDB table works as before.
- **Installers are not code-signed.**
  - On Windows, SmartScreen asks first: choose *More info*, then *Run anyway*.
  - On macOS, run `xattr -dr com.apple.quarantine "/Applications/Table Pro Max.app"` after copying the app.

  In-app updates are signed separately, and the app refuses any update the project's key did not sign.
- **Still not checked on real machines:**
  - the custom title bar on Windows and macOS;
  - window dragging on every Linux window manager;
  - updating a `.deb`/`.rpm` install from inside the app, which asks for your system password.
- **Use a least-privilege database role for production.** See [SECURITY_MODEL.md](https://github.com/ayush-eubrics01/table-pro-max/blob/v0.3.0/docs/SECURITY_MODEL.md).
