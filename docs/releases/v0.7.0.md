Table Pro Max 0.7.0 adds query parameters, SQL snippets, and pinning the tables, views and saved queries you use most to the top of the sidebar.

If you have 0.1.1 or later, the app offers this update itself: a banner appears under the title bar, or go to **Settings › Updates › Check now**.

## New
### Query parameters
- Write `:name` in a query (or `$1` on PostgreSQL and DuckDB) and run it: the app asks for each value, or NULL, before running.
- Values are sent to the database as parameters and are never written into the SQL. History keeps the query with its placeholders, not the values.
- The tab remembers the values for the next run.
- `::` casts, array slices such as `a[1:2]`, and a `:` inside strings, quoted names or comments are left alone. If a `:` wasn't meant as a parameter, choose **Run as written**.
- Values are sent as text. Comparisons with columns work as usual; MySQL `LIMIT :n` and some SQLite expressions may need a `CAST`.
- A change that uses parameters doesn't keep a restore point; the app asks before running it. EXPLAIN doesn't take parameters.

### SQL snippets
- Type a snippet's trigger word in the SQL editor and pick it from the suggestions to insert it. Tab moves between its fields.
- Three snippets to start with: `sel` (select rows), `upd` (update rows) and `cte` (common table expression).
- Add, edit and delete snippets in **Settings › Snippets**. A trigger is one word of letters, digits and `_`. Write `${name}` for each field; everything else is inserted exactly as written.
- A snippet only inserts text; nothing runs until you run it.

### Pinned objects
- Right-click a table, view, materialized view or saved query and choose **Pin to top**. A **Pinned** group heads the sidebar, in the order you pinned things.
- Pins from other schemas are shown with their schema name, and the object filter applies to them too.
- Pins are kept per connection, and per database on PostgreSQL connections with several databases. They survive restarts.
- If a pinned object is renamed or dropped, its pin shows **Not found**; right-click it to unpin.
- Pins stay on this computer. They are removed with their connection or saved query and aren't included when you export connection profiles.

## Checked
- Query parameters were run on PostgreSQL, MySQL, MariaDB, SQLite and DuckDB with every common column type. Results, RETURNING rows and the row limit come out the same as running the query with the values typed in.
- Pinned objects, parameters and snippets were tried by hand in the Linux app. The Windows and macOS builds pass the automated checks but weren't opened by hand for this release.

## Please read before installing
- After this update, older versions of Table Pro Max can't open the app's data (connections, history, saved queries), because it now stores pins and snippets. Going back to an older version isn't supported.
- Installers are not code-signed. On Windows, choose *More info* and then *Run anyway*. On macOS, run `xattr -dr com.apple.quarantine "/Applications/Table Pro Max.app"`. In-app updates are signed separately and verified before they install.
