Table Pro Max 0.11.0 adds a second editor in query tabs, binary values you can edit, folders for saved queries, and editing of MongoDB documents. It is also the first version tested through its own interface on every change.

If you have 0.1.1 or later, the app offers this update itself: a banner appears under the title bar, or go to **Settings › Updates › Check now**.

## New
### Query tabs
- **Two editors side by side.** Click the split button in the query toolbar (or press Ctrl+\\, ⌘\\ on macOS) to open a second editor next to the first. Run, Explain, Format and saving act on the editor you're in, and errors are marked in the editor that ran. Both texts are kept with the tab, also after a restart. The tab still uses one connection, so one editor runs at a time.

### Binary values
- **Edit binary cells** (bytea, BLOB, varbinary…) in an opened table: double-click a cell to paste hex (`deadbeef`, `0x…`, `\x…` or `X'…'`), load a file (up to 16 MB), set NULL, or save the stored value to a file. The change is reviewed and committed like any other edit.
- **Restore points now cover tables with binary columns** on every database; binary values come back byte for byte. Only tables whose primary key is binary still get none (except on PostgreSQL).

### Saved queries
- **Folders.** Right-click a saved query to move it into a folder (a new name makes one) or out of it; right-click a folder to rename it or delete it, with or without its queries. The sidebar filter and Ctrl+K find queries by folder name too.
- A query saved from a tab now shows in the sidebar straight away, and saving it again keeps its folder.

### MongoDB
- **Insert and edit documents.** In Find results, click the pencil on a document to edit it as JSON, or **Insert document** to add one. A save only goes through if the document is unchanged since you read it, and numbers keep their types (a 64-bit integer stays one). Not offered for vector search results (an edited embedding would no longer match what it was computed from) or for results shown with a projection. Read-only connections can't change documents; production asks first.

### Fixed
- Ctrl+K: pressing Enter right after typing opened the item that was on top before (often Settings) instead of the best match for what you typed.
- Table structure: a column you had already changed showed its old name and type, so changing it again failed at review. The row now shows the column as it will be, and a second change replaces the first.
- Import: an error loading the target table's columns disappeared when you chose a file; a `.tsv`'s tab delimiter stayed for the next `.csv`; the "Treat as NULL" box rewrote itself while you typed; read-only connections started on "A new table".
- Dashboards: charts with two columns of the same name (such as `count(*), count(*)`) could drop or repeat bars and lines when they refreshed.
- Reconnect: closing the password prompt is no longer reported as a failure; after five wrong passwords the app now says why it stopped; a failed Reconnect from a table says so.
- AI assistant: Cancel clicked right after Send now stops the request.
- Create table: the column type is required, and DuckDB is offered its own types.
- Security: the TLS certificate checks use updated libraries that no longer trust distrusted intermediate certificates (RUSTSEC-2026-0381, -0382, -0383).

## Please read before installing
- MongoDB edits keep no restore point: an edit can't be undone from the app.
- Binary values in query results can be viewed, not edited; edit them in the opened table.
- Installers are not code-signed. On Windows, choose *More info* and then *Run anyway*. On macOS, run `xattr -dr com.apple.quarantine "/Applications/Table Pro Max.app"`. In-app updates are signed separately and verified before they install.
