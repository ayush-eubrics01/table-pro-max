Table Pro Max 0.4.0 makes big tables open fast, lets you jump from a foreign key to the row it points at, and keeps a copy of the rows a change touches, so you can put them back.

If you have 0.1.1 or later, the app offers this update itself: a banner appears under the title bar, or go to **Settings › Updates › Check now**. From 0.1.0, install it by hand once; later versions then arrive in the app.

## What's new
- **Restore points.** Before an UPDATE, DELETE, TRUNCATE, DROP TABLE or ALTER TABLE … DROP COLUMN in a query tab, and before a grid commit, the app keeps a copy of the rows it changes.
  - Open them from **Restore points** in the status bar or the command palette, or from **Restore point saved · Open** under the statement in Messages.
  - Each point shows the statement and the rows before → after. **Restore all** or tick rows and **Restore selected**; the restore is shown for review before anything is written.
  - A row someone changed since stops the restore, and nothing is written. Rows already back as they were are skipped.
  - A dropped table comes back with its indexes and comments (and on PostgreSQL its `serial` numbering); a dropped column comes back with its values.
  - Inside your own transaction, a point is kept when you COMMIT and removed when you ROLLBACK.
  - A statement that can't keep one (it joins other tables, uses WITH, ORDER BY/LIMIT or MERGE, changes the primary key, the table has no primary key, …) asks first and says why.
- **Large values on demand.** Opened tables load 150 rows a page and leave long text, JSON, XML, arrays and binary columns out of the page query until you click a cell (**Not loaded**). Per column: **Load this column**, **Always load** or **Don't load**. Long values in query results show a preview and open in full on click. JSON and JSONB open in a JSON editor that checks the JSON before saving and formats it without changing values; long text opens in a text editor. Export and copy always use full values.
- **Jump to the referenced row.** A foreign-key cell has a small arrow (also Ctrl/⌘+Enter, or **Open referenced row** in its menu) that opens the referenced table in a new tab, filtered to that row. It works in opened tables and in query results the app can trace to their table, including keys over several columns.

## Security
- **TLS library updated** (rustls 0.23.46) for four advisories published on 2026-10-14 (RUSTSEC-2026-0346 to 0349). The most serious could expose TLS secrets through debug output; the others concern downgrade and memory use during the TLS handshake. It covers database connections, the optional AI endpoint and the update check.

## Please read before installing
- **Restore points keep table data on this computer**, in the app's own database, not encrypted, for 7 days by default, within the limits in **Settings › Safety** (100,000 rows and 50 MB per point, 1 GB in all; the oldest go first). They are on for every connection, production included. Turn them off per connection under **Safety & timeouts** if copies of that data must not be stored. They never leave the computer.
- **Restore points are not a backup.** Not covered: INSERT (including upserts and REPLACE), SQL files run from disk, read-only connections, Redis, and the cases the app asks about first. A table without a primary key can only be restored all at once, once.
- **Each covered statement does a little more work:** a bounded count before it runs, and a read of the rows it changes, in the same transaction. On very wide or very large changes, expect them to take longer; over the row limit, the app asks before running without a restore point.
- **Installers are not code-signed.**
  - On Windows, SmartScreen asks first: choose *More info*, then *Run anyway*.
  - On macOS, run `xattr -dr com.apple.quarantine "/Applications/Table Pro Max.app"` after copying the app.

  In-app updates are signed separately, and the app refuses any update the project's key did not sign.
- **Still not checked on real machines:**
  - the custom title bar on Windows and macOS;
  - window dragging on every Linux window manager;
  - updating a `.deb`/`.rpm` install from inside the app, which asks for your system password.
- **Use a least-privilege database role for production.** See [SECURITY_MODEL.md](https://github.com/ayush-eubrics01/table-pro-max/blob/v0.4.0/docs/SECURITY_MODEL.md).
