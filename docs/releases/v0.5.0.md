Table Pro Max 0.5.0 makes production connections harder to change by accident.

If you have 0.1.1 or later, the app offers this update itself: a banner appears under the title bar, or go to **Settings › Updates › Check now**.

## Please read first
**After this update, production connections open read-only.** Nothing is lost and no setting of yours changes. To change data, choose **Allow writes** in the status bar and type the connection's name. To keep the old behaviour, turn off **Settings › Safety › Open production connections read-only**.

## New
### Production opens read-only
- Connections whose environment is Production open read-only. The database session itself refuses writes, not only the app.
- **Allow writes** in the status bar asks you to type the connection's name, then reconnects with writes on, for that connection window only. Query tabs reconnect on their next run.
- **Back to read-only** turns writes off again.
- Writes are never remembered: reconnecting, restarting the app, or reopening your tabs at startup opens read-only again.
- Connections already set to **Read-only** stay read-only, and there is no Allow writes for them.
- On DuckDB, the app blocks writes itself, because one file can't be open read-only and writable at the same time. Redis connections are not covered by either change.

### Type the name to confirm, on production
On production connections, statements that destroy data need the connection's name typed instead of a click:
- DROP and TRUNCATE;
- UPDATE or DELETE without a WHERE;
- ALTER … DROP;
- CREATE OR REPLACE TABLE.

This applies in query tabs, **Run SQL file**, EXPLAIN ANALYZE, **Drop table** in the sidebar and the structure editor. On SQLite, changing a table's structure rebuilds the table, so it asks too. The check runs in the app's backend, not only in the dialog. A connection set to **Run everything** still never asks.

## Fixed
- Long file paths and host names wrap in confirmation dialogs instead of widening them.

## Security
- The in-app updater no longer contains code to unpack zip archives. It never used it, because updates ship as plain installers. This removes the only place in the app where three new advisories for the `zip` library (RUSTSEC-2026-0367, -0368, -0369) could have applied. The other two copies of that library never unpack archives in the app; the reasons are in `docs/DECISIONS.md` (D16).

## Please read before installing
- Installers are not code-signed. On Windows, choose *More info* and then *Run anyway*. On macOS, run `xattr -dr com.apple.quarantine "/Applications/Table Pro Max.app"`. In-app updates are signed separately and verified before they install.
