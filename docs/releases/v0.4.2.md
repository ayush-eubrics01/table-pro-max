Table Pro Max 0.4.2 is a bug-fix release for 0.4.1. It has no new features.

If you have 0.1.1 or later, the app offers this update itself: a banner appears under the title bar, or go to **Settings › Updates › Check now**.

## Fixed

### Large values and JSON
- **Typing into a JSON cell opens the JSON editor**, so the JSON check always runs. Before, typing started a plain inline edit.
- **A Not loaded value opens for editing in one gesture.** Enter or double-click loads it and starts the edit; before, it could take a second try.
- **JSON in query results opens in the JSON editor** on PostgreSQL read-only connections and inside a transaction too. Before, those results had no column types, so JSON opened as plain text.
- **Result-grid rough edges:**
  - editing a row that someone deleted meanwhile says "Refresh to see the current rows";
  - a result that is no longer in memory offers **Run again**;
  - **Set to NULL** also covers Not loaded cells.

### Jump to referenced row
- **The arrow's tooltip reads like the filter it opens**, for example "Open customers where id = '42'".
- **Keys stored as numbers are found** in SQLite columns with no declared type and in MySQL `FLOAT`/`DOUBLE` columns. Before, the new tab could show No rows.
- **The arrows also appear in query results on PostgreSQL read-only connections.**

### Restore points
- **A statement that matched nothing says so:** "No restore point: no rows matched".
- **A warning when the saved rows may not match the change.** If a statement changed more or fewer rows than were read just before it ran (a WHERE with `random()`, or rows another session added in between), the restore point is kept and Messages says what to check.
- **PostgreSQL locks the table before saving it for TRUNCATE or DROP**, so no row can be added between the save and the statement.
- **SQLite saves can't fail because another program wrote to the file at the same moment.** The app now takes the write lock before it reads.
- **DuckDB generated columns are recognised.** Restoring rows into such a table works now (before, nothing was written), and the column's expression is no longer shown as its default.

## Worth knowing
- On PostgreSQL read-only connections, each SELECT in a query tab now makes one extra small round trip to the server to learn the result's column types. Writable connections already did this.

## Please read before installing
- Installers are not code-signed. On Windows, choose *More info* and then *Run anyway*. On macOS, run `xattr -dr com.apple.quarantine "/Applications/Table Pro Max.app"`. In-app updates are signed separately and verified before they install.
